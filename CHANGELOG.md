# Changelog — Calculos Online

Funcionalidades entregues em produção. Versionamento SemVer (`Major.Minor.Patch`)
do app `web` (`apps/web/package.json`): `minor` para nova funcionalidade, `patch`
para ajuste/correção, `major` para marco de estabilização. Histórico anterior à
estabilização fica em `0.x`.

- **Stack atual:** Next.js `15.5.18` (React `19.0.0`), monorepo Turborepo com
  `packages/core` (cálculos) e `packages/ui` (componentes) versionados à parte.
- **Coluna Versão:** versão de `apps/web` *após* aquela entrada.
- Entradas mais recentes no topo. Datas em `AAAA-MM-DD`. `Commit` = commit principal.

| 2026-07-20 | **0.3.0** | **Fix do lastmod do sitemap + schema HowTo + chips de valor rápido (padrão Recibo Fácil).** Paulo notou em produção que o `lastmod` das calculadoras no sitemap ainda mostrava datas antigas mesmo após a entrega de 0.1.0/0.2.0 — causa: `app/sitemap.ts` usava `calc.dataAtualizacao` puro (data de revisão das tabelas legislativas, fixa em `2026-01-01` para as 20 calculadoras, também exibida ao usuário como selo de confiança) como único sinal de freshness, então uma mudança de SEO (title/FAQ) sem alteração das tabelas não movia o `lastmod`. Fix: nova constante `seoRefreshDate` (bumpada manualmente a cada mudança de SEO relevante, mesmo padrão do recibofacil) — o `lastmod` de cada calculadora agora usa a mais recente entre `dataAtualizacao` e `seoRefreshDate`, sem alterar o que é mostrado ao usuário como data de revisão legislativa. **Schema HowTo** adicionado em `apps/web/src/lib/schema.ts` (3 passos genéricos por calculadora: preencher, calcular, ver detalhamento) — fecha a lacuna do plano de negócios (seção 3.1) que pedia `HowTo`/`FAQPage` para rich snippets e nunca tinha sido implementado; `seo-metadata.spec.ts` atualizado para cobrir. **Chips de valor rápido** — portado o `CurrencyInputWithQuickAdd` do recibofacil (mesmas classes Tailwind: chip cinza "Zerar" + chips azuis "+N") como opção `quickAdd` em `FieldMeta` do `CalculatorForm` compartilhado (`packages/ui`): "Zerar" zera o campo, cada chip **soma** ao valor atual (não substitui, arredondado a 2 casas). Aplicado no campo de valor principal de 16 formulários / 17 calculadoras com campo R$ (todas exceto IMC/Calorias/Porcentagem, que não têm campo monetário), com 3 presets por escala (`QUICK_ADD_SALARIO`, `QUICK_ADD_INVESTIMENTO`, `QUICK_ADD_VALOR_GRANDE` em `apps/web/src/lib/quickAddPresets.ts`). Novo `quick-add-chips.spec.ts` (5 testes: soma cumulativa, zerar, soma a partir de vazio, campo sem `quickAdd` não ganha chips, preset de investimento). Validação: `pnpm typecheck` + `pnpm lint` + `pnpm build` limpos, 22/22 e2e verdes (17 anteriores + 5 novos). | `_pendente_` |
| 2026-07-19 | **0.2.0** | **Playwright E2E + sitemap/robots nativos (padrão Recibo Fácil) + fix crítico de validação.** `apps/web/playwright.config.ts` + `tests/e2e/` (mesmo padrão do Recibo Fácil: `testDir`, reaproveita dev server, projeto único `chromium`): `calculadora-margem-lucro.spec.ts` (fluxo completo do form ao resultado, referência para as outras 19 calculadoras), `seo-metadata.spec.ts`, `sitemap-robots.spec.ts`, `categorias-navegacao.spec.ts` — 17 testes. `next-sitemap` removido (dependência, config, script `postbuild`, `public/sitemap.xml`/`public/robots.txt` estáticos) e substituído por `app/sitemap.ts`/`app/robots.ts` nativos do Next, no mesmo padrão do Recibo Fácil: `lastModified` real por calculadora (`calc.dataAtualizacao` do registry, não data de build) e prioridade maior (0.95) para calculadoras `featured`; corrige também um bug do sitemap antigo, que listava `/privacidade` (rota que só redireciona) em vez da canônica `/politica-de-privacidade`. **Bug crítico encontrado pelo próprio teste novo, não estava no escopo original:** campo numérico opcional deixado em branco virava `NaN` via `valueAsNumber` do react-hook-form, e o `.default(0)` do Zod só resgata `undefined`, nunca `NaN` — travando a submissão com "Expected number, received nan". Corrigido na raiz, em `packages/ui/src/CalculatorForm/index.tsx` (troca de `valueAsNumber` por `setValueAs` com tratamento explícito de string vazia), valendo para todas as calculadoras de uma vez. Validação: `pnpm typecheck` + `pnpm lint` + `pnpm build` limpos, 322 testes unitários do core verdes, 17/17 e2e verdes. | `964bde0` |
